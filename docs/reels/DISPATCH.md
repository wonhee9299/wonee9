# 작업 위임 프로토콜 (폰 → 클라우드 Claude → PC Claude)

## 구성

사용자는 폰에서 **클라우드 세션**에 명령한다. 클라우드 세션은 로그인된 브라우저와
원본 파일이 없으므로, 실제 실행이 필요한 작업은 **PC 세션으로 넘긴다.**

```
사용자(폰) ──명령──> 클라우드 Claude ──트리거──> PC Claude ──실행──> 인스타/파일/NAS
                          ^                          |
                          └────── git push ──────────┘
                                  (결과 회신)
```

- **내보내기**: 트리거(`create_trigger` + `fire_trigger`, `persistent_session_id` 지정)
- **되받기**: PC 세션이 `handoff/` 에 결과를 커밋·푸시 → 클라우드가 `git fetch` 로 읽음

트리거는 단방향이라 결과가 자동으로 돌아오지 않는다. **git 이 회신 통로다.**

## 클라우드 세션이 하는 일

1. 작업 명세를 만든다 — 무엇을, 어떤 값으로, 어떻게 검증할지까지 구체적으로.
   PC 세션은 이쪽 대화 맥락을 모르므로 **단독으로 실행 가능한 지시**여야 한다.
2. `create_trigger` 에 `persistent_session_id` 로 PC 세션 ID를 지정하고 `fire_trigger` 로 발사.
3. 결과는 `git fetch origin <브랜치> && git log`, `handoff/` 확인으로 읽는다.
4. 다 끝난 트리거는 `delete_trigger` 로 정리한다. 남겨두면 나중에 다시 발사될 수 있다.

작업 명세에 반드시 포함할 것:

- 대상 (URL, 파일 경로, 계정, 댓글 작성자 등 식별자)
- 그대로 써야 하는 문안·좌표·명령은 **원문 그대로** (임의 수정 금지 명시)
- 검증 방법 (게시 후 재조회, 블러 영역 확대 확인 등)
- **하지 말 것** (예: 스토리는 폰 앱 전용이니 시도 금지, 특정 댓글 무대응)
- 끝나면 `handoff/` 에 결과 기록 후 커밋·푸시

## PC 세션이 하는 일

트리거로 작업을 받으면:

1. 작업을 수행한다. 사용자 승인이 필요한 지점(최종 게시 등)은 `CLAUDE.md` 규칙을 따른다.
2. 결과를 `handoff/results/YYYY-MM-DD-<작업이름>.md` 에 기록한다. 형식:

```markdown
# <작업 이름>
- 상태: 완료 | 부분완료 | 실패 | 사용자입력대기
- 실행 시각:
- 한 일:
- 확인한 것: (게시 URL, 재조회 결과, 스크린샷 경로 등)
- 안 된 것 / 막힌 것:
- 다음에 필요한 것:
```

3. 커밋·푸시한다. 이게 클라우드 세션에 결과를 알리는 유일한 방법이다.
4. 사용자에게도 짧게 보고한다.

**실패해도 반드시 기록한다.** 조용히 끝내면 클라우드 쪽은 아직 진행 중인지 실패인지 알 수 없다.

## 전제 조건

- **PC에 Claude Code 세션이 살아 있어야 한다.** `claude remote-control` 을 띄워두거나
  `/config` 의 자동 연결을 켜둔다. 설정은 `REMOTE_CONTROL_SETUP.md` 참고.
- PC가 절전/종료되면 트리거가 도달하지 않는다. 작업 전에 PC 상태를 확인한다.
- 트리거로 뜬 세션은 **MCP 커넥터 없이** 실행된다. 커넥터가 필요한 작업은 이 경로로 넘기지 않는다.

## 한계

| | 상태 |
|---|---|
| 클라우드 → PC 작업 발사 | 됨 (트리거) |
| PC → 클라우드 결과 회신 | 됨 (git push, 자동은 아니고 클라우드가 fetch) |
| 실시간 양방향 대화 | 안 됨 |
| PC 세션 상태 조회 | `list_sessions` 로 연결 여부만 확인 가능 |

실시간으로 주고받아야 하는 작업이면 폰에서 **PC 세션을 직접 골라** 명령하는 게 낫다.
위임은 "던져놓고 나중에 결과 확인"에 맞는 방식이다.
