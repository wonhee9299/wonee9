# DSM 설정과 문제 해결

## 1. NAS 쪽 준비

### File Station 켜기
File Station은 DSM에 기본 설치되어 있습니다. 없다면 **패키지 센터**에서 설치하세요.
이 도구는 File Station 웹 API로만 동작하므로, SSH를 열 필요가 없습니다.

### 전용 계정 만들기 (권장)
관리자 계정 대신 백업 전용 계정을 쓰면 사고 범위가 줄어듭니다.

**제어판 → 사용자 및 그룹 → 생성**
- 권한: 작업을 저장할 공유 폴더에만 `읽기/쓰기`
- 응용 프로그램 권한: `File Station` 만 허용, 나머지는 거부
- 관리자 그룹에는 넣지 않습니다

### 저장 위치 정하기
`NAS_BASE_PATH` 는 반드시 **공유 폴더 이름으로 시작**해야 합니다.

| 값 | 실제 위치 |
|----|-----------|
| `/home/work` | 로그인 계정의 개인 홈 폴더 안 `work` (사용자 홈 서비스가 켜져 있어야 함) |
| `/volume1/work` | `work` 라는 공유 폴더 |
| `/공유/백업` | `공유` 공유 폴더 안 `백업` |

`/volume1/homes/...` 같은 내부 경로가 아니라, File Station 왼쪽 트리에 보이는
이름을 그대로 쓰면 됩니다. 하위 폴더는 없으면 자동으로 만들어집니다.

## 2. 접속 주소 정하기

### 내부망 (같은 집/사무실)
```
SYNOLOGY_URL=http://192.168.0.10:5000
```
IP는 **DSM → 제어판 → 정보 센터 → 네트워크** 에서 확인합니다.
공유기에서 NAS의 IP를 고정(DHCP 예약)해 두면 주소가 바뀌지 않습니다.

### 외부망
포트를 그대로 인터넷에 여는 것은 권하지 않습니다. 안전한 순서대로:

1. **Tailscale / VPN** — 포트를 열지 않고 어디서든 내부망처럼 접속.
   NAS에 Tailscale을 설치한 뒤 그 주소를 `SYNOLOGY_URL` 에 넣습니다.
2. **QuickConnect + DDNS + 정식 인증서** — **제어판 → 외부 액세스** 에서 DDNS를
   등록하고 Let's Encrypt 인증서를 발급받은 뒤:
   ```
   SYNOLOGY_URL=https://내이름.synology.me:5001
   SYNOLOGY_VERIFY_SSL=true
   ```
3. 어느 경우든 **제어판 → 보안 → 계정**에서 자동 차단과 2단계 인증을 켜세요.

## 3. 2단계 인증

2단계 인증을 켠 계정은 OTP 없이 로그인할 수 없습니다. 코드는 30초마다 바뀌므로
`.env` 에 적어두면 금방 무용지물이 됩니다. 실행할 때마다 넘기세요.

```bash
SYNOLOGY_OTP=123456 ./nas snapshot
```

자동 백업(cron)까지 무인으로 돌리려면, 그 용도의 계정에서는 2단계 인증을 끄고
대신 권한을 특정 공유 폴더로만 좁히는 편이 현실적입니다.

## 4. 문제 해결

| 증상 | 원인과 해결 |
|------|-------------|
| `NAS에 연결할 수 없습니다` | 주소나 포트가 틀렸거나 다른 네트워크에 있음. `ping <NAS IP>` 로 먼저 확인 |
| `[400] 계정이 없거나 비밀번호가 틀림` | DSM 계정/비밀번호 확인. 이메일이 아니라 **DSM 사용자 이름** 입니다 |
| `[403] 2단계 인증 코드가 필요함` | `SYNOLOGY_OTP=코드 ./nas ...` 형태로 실행 |
| `[407] IP가 차단됨` | 로그인 실패가 반복되어 자동 차단됨. **제어판 → 보안 → 계정 → 차단 목록** 에서 해제 |
| `TLS 인증서 검증 실패` | DSM 기본 자체 서명 인증서. 내부망이라면 `SYNOLOGY_VERIFY_SSL=false`, 외부망이라면 정식 인증서 발급 |
| `[105] 권한 없음` | 계정에 File Station 응용 프로그램 권한이 없거나 해당 공유 폴더 쓰기 권한이 없음 |
| `[408] 해당 경로의 파일 또는 폴더가 없음` | `NAS_BASE_PATH` 의 공유 폴더 이름 확인. File Station 트리에 보이는 이름과 같아야 함 |
| `[1805] 업로드가 허용되지 않음` | 공유 폴더가 읽기 전용이거나 계정 권한이 읽기 전용 |
| `[106] 세션 만료` | 오래 걸리는 작업 중 세션이 끊김. 다시 실행하면 새로 로그인합니다 |
| `FileStation API를 찾을 수 없습니다` | File Station 패키지가 설치·실행되지 않음 |

### 그래도 안 될 때
어느 단계에서 막히는지 좁혀 봅니다.

```bash
./nas check     # 로그인까지 되는지
./nas ls        # 기준 경로를 읽을 수 있는지
./nas ls /      # 공유 폴더 목록이 보이는지 (경로 이름 확인용)
```

`./nas ls /` 는 실제 공유 폴더 이름을 보여주므로, `NAS_BASE_PATH` 를 맞추는 데
가장 빠른 방법입니다.

## 5. 용량 관리

스냅샷은 지우지 않으면 계속 쌓입니다. 오래된 것을 정리하려면 File Station에서
`snapshots/<프로젝트>/` 를 열어 지우거나, DSM의 **작업 스케줄러**에 정리 작업을
등록하세요. 진짜 백업이 필요하다면 NAS 자체를 **Hyper Backup** 으로 외부에
한 벌 더 복사해 두는 것을 권합니다 — NAS 한 대는 백업이 아니라 저장소입니다.
